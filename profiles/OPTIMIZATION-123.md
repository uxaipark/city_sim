# 선택 항목 1·2·3 구현 및 검증

2026-09-27. 기존 병목 측정은 [REPORT.md](REPORT.md), 이번 변경 전 브라우저 비교 측정은 [before-123-fresh.json](before-123-fresh.json)에 보관했다.

## 변경

1. 블룸: EffectComposer의 논리 크기를 CSS 크기로 설정해 DPR 중복 적용을 제거했다. 넓은 블룸은 기본 블룸의 절반 크기를 리사이즈 후에도 유지한다. 블러 샘플 간격을 보정해 기존 화면상의 번짐 범위를 유지한다. 메인 해상도·MSAA·그림자 해상도는 유지한다. 낮은 블룸 해상도에 따른 픽셀 단위 차이는 있을 수 있으며 최종 시각 비교는 미완료다.
2. 나무: 기존 20종·60,492그루의 모형·위치·색을 그대로 유지하면서 291개 공간 묶음을 추가했다. 카메라와 그림자 범위에서 처리할 인스턴스가 충분히 줄 때만 공간 묶음을 사용하고, 도시 전체가 보이면 기존 수종별 묶음을 사용한다. 지오메트리와 재질은 공유하며 인스턴스 버퍼는 추가 메모리를 사용한다.
3. 보행자: 도로별 인원 인덱스와 공간별 렌더 인덱스를 도입했다. 시뮬레이션과 출력은 기존 인원 ID 순서를 유지해 난수 호출 순서·이동·옷 색을 보존한다. 넓은 화면에서는 순차 스캔을 사용해 인덱스 순회 비용을 제한한다.

## 검증

- `npm run build` 통과. 번들 크기 경고는 남아 있다.
- `node scripts/profiler-test.mjs` 통과: 13개 조건의 측정 수와 효과 복원 검증.
- `node scripts/spatialcheck.mjs /tmp/city-sim-before123` 통과: 900프레임, 밀도 변경·관찰 지점 이동·순간 이동·숨김 전환을 포함한 보행자 상태, 난수 순서, 렌더 인원 ID·위치·색 동일성 검증.
- 나무 인스턴스 위치·색·수량 동일성, 지오메트리·재질 공유, 바람을 포함한 보수적인 경계 구 검증.
- DPR 1/1.5/2와 반복 리사이즈에서 블룸 크기 및 블러 샘플 간격 검증.
- 마지막 로컬 회귀 실행의 보행자 시뮬레이션 평균은 1.93 → 1.77ms, 렌더 배열 구성은 2.24 → 1.94ms였다. JIT 준비와 실행 조건이 섞인 회귀 테스트이므로 일반적인 개선율이나 브라우저 FPS로 해석하면 안 된다.
- 고정 근거리 카메라·그림자 범위의 나무 처리 추정치는 전체 묶음 120,984 → 공간 묶음 29,396 인스턴스(본 화면+그림자)였다. 전체 도시 시점에서는 기존 40회 draw를 유지한다. 근거리에서는 132회로 늘어나는 비용이 있다. 이는 실제 GPU 시간 측정이 아니다.

최종 변경 후 통제된 브라우저 FPS 측정과 낮·야간 시각 비교는 아직 완료하지 못했다. 따라서 전체 FPS 향상이나 블룸의 시각적 동일성을 확정하지 않는다. 재측정은 `node scripts/profile-server.mjs profiles/after-123.json` 실행 후 `http://127.0.0.1:5173/?profile=compare`에서 네 시점을 측정한다. 측정 중 탭과 카메라, 창 크기를 유지해야 한다.

## Rust 검토

기존 측정에서 JavaScript 작업은 약 10ms, 전체 프레임은 약 49ms였다. 블룸 등 GPU 렌더링이 주 병목이므로 Rust로 CPU 코드만 이식해도 전체 FPS 개선은 제한될 수 있다. 차량 CPU 계산을 분리한 Rust/WebAssembly 모듈과 Web Worker를 다음 실험 대상으로 권한다. HTTP 서버 호출을 매 프레임 추가하는 구조는 직렬화·통신·동기화 비용을 먼저 검증해야 한다. 이번 변경에는 Rust 이식을 포함하지 않았다.
